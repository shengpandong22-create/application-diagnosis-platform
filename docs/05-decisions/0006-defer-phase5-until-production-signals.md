# ADR-0006：在生产信号出现前暂缓 Phase 5

> [返回文档导航](../README.md)

## 状态

Accepted

## 背景

Phase 5 已设计为融合服务目录、API 网关路由、Nacos 实例和运行时 Trace 的跨服务因果诊断。该方向有企业价值，但个人电脑上的少量模拟服务无法证明拓扑时效性、Trace 完整性、实例漂移和跨团队权限治理。

Phase 0～4 已形成从被动诊断、Evidence、人工确认、服务目录到日志主动发现的闭环。真实模型评测进一步暴露的首要问题是工具搜索空间和预算收敛，而不是缺少跨服务拓扑。

## 决策

暂缓 Phase 5 代码实施，保留现有设计规格。当前优先维护诊断闭环、确定性测试、真实模型失败模式和单服务工具约束。

当以下任一条件被真实数据满足时，重新评审 Phase 5：

- 已确认诊断中跨服务故障占比连续两期超过 30%；
- 至少接入两个真实服务，并能稳定获得网关路由、Nacos 实例和 Trace ID；
- 单服务 Evidence 无法解释的案例形成可复现样本；
- 有明确使用方承担拓扑数据授权、保留周期和脱敏责任。

## 备选方案

立即用本地模拟数据开发完整拓扑。未采用，因为它容易形成展示性图谱，却无法验证生产环境最困难的数据一致性与权限问题。

彻底取消 Phase 5。未采用，因为跨服务因果是服务目录成熟后的自然演进，只是尚未满足投入条件。

## 影响

- README 使用触发器表代替模糊的“未来企业化”表述；
- 面试中可以解释为什么暂缓，而不是把未实现能力包装为已完成；
- Phase 5 重启时必须先准备真实样本与数据契约，再决定 Nacos、网关和 Trace Adapter；
- 当前不新增拓扑数据库、分布式 Worker 或模拟微服务集群。
