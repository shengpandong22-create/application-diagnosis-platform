# ADR-0004：可持久化的有界 Tool Loop

> [返回文档导航](../README.md)

## 状态

Accepted

## 决策

最小 Agent Loop 由独立的 `ToolLoopRunner` 编排，不放入 API、领域实体、LLM Adapter 或具体工具中。每次运行创建 `AgentRun`，每次工具调用创建 `ToolRun`，持久化只记录审计所需的状态、耗时、校验后参数、结果与错误，不保存完整提示词历史。

循环必须同时受模型轮次、工具调用次数、单工具超时和总执行时间约束。模型返回的工具参数先经过 Registry 的白名单、权限和 Schema 校验，再允许执行。结构化最终结论校验失败时最多进行一次纠错；超出预算、所有工具失败、内容被截断或过滤时，运行以可解释的 `inconclusive` 结果收敛。

## 扩展结果

- 应用用例只负责加载诊断案例、选择策略和调用 Runner；
- API 只负责协议转换，不直接维护对话循环；
- Phase 0B 可在不改变循环核心的情况下加入 Evidence、人工确认和持久化上下文；
- Phase 1 可增加日志、指标和代码检索工具，但仍使用统一 Registry、预算与审计机制；
- 若以后引入 LangGraph，它应作为另一种 Workflow Adapter 使用现有 Port 和领域契约，而不是替换领域模型。

## 取舍

- 短事务会增加少量数据库写入，但避免在等待模型或工具期间长期占用事务；
- 不保存完整提示词降低了敏感信息泄漏和存储成本，但 Phase 0 的逐 token 回放能力有限；
- 失败统一收敛为可审计状态，使早期实现更可靠，但复杂恢复与断点续跑推迟到后续阶段。

## ITOps 参考

只参考其 Agent Loop、Provider 和工具编排的职责划分，不复用 TypeScript 运行时、全局 Registry、副作用初始化或具体 Workflow 实现。
