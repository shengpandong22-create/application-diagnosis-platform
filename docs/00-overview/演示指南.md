# 离线演示指南

> [返回文档导航](../README.md)

本项目默认把自动测试和离线演示都设计成 Fake LLM，不访问外部模型、不读取 `.env` 中的真实 API Key。只有明确运行真实模型脚本或启动 API 后触发真实 Run，才可能产生模型调用费用。

## Phase 0：最小诊断闭环

```powershell
uv run python scripts/demo-phase0.py
```

演示链路：

```text
创建诊断 → 输入脱敏 → knowledge__search → Evidence → Citation Policy → 人工确认 → Report
```

输出：

- `demo-output/demo-summary.json`
- `demo-output/diagnosis-report.md`

## Phase 1：源码联合诊断

```powershell
uv run python scripts/demo-phase1-code.py
```

演示链路：

```text
用户日志 → code__search → code__read → code_excerpt Evidence → Report
```

如果本地 Java Lab 已经产生真实日志，也可以运行：

```powershell
uv run python scripts/demo-phase1-log-code.py --keyword NullPointerException
```

这条链路会从受限日志目录读取最近一次相关异常，再结合受限源码进行诊断。

## Phase 2：Trace、多策略与现场工具

```powershell
uv run python scripts/demo-phase2.py
```

演示链路：

```text
配置类故障 → Strategy Router → config__read → config_excerpt Evidence → Trace
```

重点展示：

- 多 Strategy 路由；
- 配置读取脱敏；
- Trace 中可查看工具调用和 Evidence ID。

## Phase 3C：服务目录驱动工具上下文

```powershell
uv run python scripts/demo-phase3-service.py
```

演示链路：

```text
ServiceProfile → 通过服务创建诊断 → ToolResourceContext
→ Strategy 动态工具白名单 → code__search/code__read
→ code_excerpt Evidence → Trace → Report
```

这个脚本会创建临时服务目录，不依赖你电脑上的真实 Java Lab，也不会调用真实模型。

输出：

- `demo-output/phase3-service/demo-summary.json`
- `demo-output/phase3-service/trace.json`
- `demo-output/phase3-service/diagnosis-report.md`

## 真实模型脚本

```powershell
uv run python scripts/diagnose-java-log-real.py --keyword NullPointerException
```

这条脚本会读取 `.env` 中配置的真实模型信息并调用外部模型，可能产生费用。运行前需要确认：

- `.env` 已配置模型；
- Java Lab 已产生目标故障日志；
- 你允许将脱敏后的日志/源码片段发送给模型服务商。

## 本地界面

```powershell
uv run alembic upgrade head
uv run uvicorn app_diagnosis.api.app:create_app --factory --reload
```

打开：

- 极简界面：`http://127.0.0.1:8000/ui`
