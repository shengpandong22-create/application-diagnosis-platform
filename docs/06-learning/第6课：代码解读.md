# 主动发现链路 · 代码逐步骤解读

对应第 6 课。理解一条异常日志如何经过 Fingerprint → Incident → TriggerPolicy 决策，最终复用被动诊断主体流程。

## 概述：主动发现只做一件事

主动发现在主调用链 8 步中的位置——它在 `[1]` 之前多了一段预处理，然后复用了 `[1]~[8]` 的全部逻辑。

### 关键代码（application/discovery.py 第 52-53 行）

```python
async def discover(self, source: LogEventSource) -> tuple[DiscoveryResult, ...]:
    return tuple([await self.process(event) for event in await source.collect()])
```

### 步骤 1：日志事件 → LogEvent

`discover()` 从 `LogEventSource` 获取事件。Source 的实现有两种：`FileLogEventSource`（Phase 4C 本地文件）和 `ReplayLogEventSource`（Phase 4C 重放测试）。两者都实现同一个抽象接口，互不感知。

### 步骤 2：LogEvent → Incident 聚合

源码位置：application/discovery.py 第 58-67 行

```python
aggregation = await self._incidents.ingest(
    service_id=event.service_id,
    environment=event.environment,
    occurred_at=event.occurred_at,
    severity=event.severity,
    message=event.message,
    exception_type=event.exception_type,
    stack_frames=event.stack_frames,
    source_event_id=event.source_event_id,  # ← 交给DeduplicationStore做消息级幂等
)
```

#### 2.1 ingest 做了什么

`IncidentApplicationService.ingest()` 内部调用 `build_error_fingerprint(event)` → 生成稳定指纹（取前 5 个业务栈帧的 `class#method`，去行号、数字归一化）→ 查找同服务同环境下是否存在同指纹的 Incident。

- 已存在：`Incident.observe(event)` → `occurrence_count++`，更新 `last_seen_at`
- 不存在：创建新 Incident（`occurrence_count=1`，`is_novel=True`）

#### 2.2 source_event_id 防重放

如果 `source_event_id` 已处理过 → `duplicate_event=True`，后续 `TriggerPolicy` 直接跳过。

### 步骤 3：TriggerPolicy 决策

源码位置：application/discovery.py 第 76 行 + domain/incident/trigger.py

```python
decision = self._trigger_policy.decide(aggregation)
if not decision.should_trigger:
    return DiscoveryResult(incident=current, triggered=False, ...)
```

`DiagnosisTriggerPolicy.decide()` 的核心逻辑（`trigger.py` 第 15-20 行）：

```python
def decide(self, aggregation):
    if aggregation.duplicate_event:
        return TriggerDecision(False, "duplicate_source_event")        # ① 重放
    if aggregation.incident.diagnosis_id is not None:
        return TriggerDecision(False, "diagnosis_already_linked")     # ② 已关联诊断
    return TriggerDecision(True, "incident_without_diagnosis")        # ③ 触发
```

三个不触发的场景：

- ① `duplicate_event`：同一个 `source_event_id` 已被当前装配的DeduplicationStore声明；默认应用装配使用SQLAlchemy实现，Redis是可选企业Adapter
- ② `diagnosis_id is not None`：Incident 已经绑了一个 Diagnosis（不管那个 Diagnosis 是什么状态）
- ③ 都不满足 → 触发

### 步骤 4：创建 Diagnosis + 绑定 Incident

源码位置：application/discovery.py 第 85-94 行

```python
diagnosis = await self._diagnoses.create(
    service_id=event.service_id,
    title=f"Auto-discovered {event.exception_type}",
    symptom=f"Incident {current.id} detected ... fingerprint={current.fingerprint[:12]}",
    submitted_log=current.sample_message,
)
current = await self._incident_repository.link_diagnosis(current.id, diagnosis.id)
```

关键时序：`link_diagnosis()` 在创建 Diagnosis 之后、`run()` 之前调用。这样即使后续 `run()` 失败（例如 LLM 超时），Incident 也已经绑定了 Diagnosis——防止同一个 Incident 被重复触发诊断。

### 步骤 5：写入自动触发 Evidence

源码位置：application/discovery.py 第 95-114 行

```python
await self._evidence_store.add_candidates(
    diagnosis.id,
    (EvidenceCandidate(
        type="user_statement",
        source="local_service",
        content=f"Automatically triggered from incident {current.id}; "
                f"fingerprint version {current.fingerprint_version}; "
                f"occurrence count {current.occurrence_count}.",
        metadata={"incident_id": str(current.id), "automatic_trigger": True, ...},
    ),),
)
```

这条 Evidence 记录了触发上下文（哪个 Incident、第几次发生、为什么被触发）。后续 `CitationPolicy` 可以校验结论是否引用了这条"触发原因"证据。

### 步骤 6：调用被动诊断主体流程

源码位置：application/discovery.py 第 127-150 行

```python
run = await self._diagnoses.run(
    diagnosis.id,
    actor="active-discovery",
    environment=event.environment,
    correlation_id=str(current.id),
    max_tool_output_bytes=self._max_tool_output_bytes,
)
```

`self._diagnoses` 的类型是 `EvidenceAwareDiagnosisApplicationService`——和被动诊断用的是同一个类的同一个实例。它调用 `run()` → 触发 8 步主调用链。

### 步骤 7：失败处理 + 返回

```python
except Exception as error:
    return DiscoveryResult(
        incident=current,
        diagnosis_id=diagnosis.id,
        triggered=True,
        trigger_reason=decision.reason,
        error_code=type(error).__name__,
    )
```

设计解读（注释第 142 行）："`AgentRun`/`ToolRun` 由 `Runner` 自己持久化；这里返回安全错误码以便后续重放检查。"

这意味着即使主动发现的 `run()` 失败了，Incident 已经绑定了 Diagnosis（步骤 4 已完成），Evidence 也写入了（步骤 5 已完成），`AgentRun` 由 `Runner` 在内部逐步持久化——失败是可追踪的，不会产生"既没有诊断记录也没有绑定"的悬空状态。

## 主动发现链路速查

| 步骤 | 关键代码 | 文件 | 核心职责 |
| --- | --- | --- | --- |
| 日志采集 | `source.collect()` | `ports/log_event_source.py` | 从文件或重放源获取事件 |
| 事件 → Incident | `incidents.ingest()` | `application/incidents.py` | Fingerprint 聚合 + `occurrence_count` |
| 触发决策 | `trigger_policy.decide()` | `domain/incident/trigger.py` | 三点判断：重放/已关联/触发 |
| 创建 Diagnosis | `diagnoses.create()` | `evidence_diagnoses.py` | 自动生成标题和症状 |
| 绑定 Incident | `link_diagnosis()` | `incident_repository` | `diagnosis_id` 绑定（不可解绑） |
| 写入 Evidence | `evidence_store.add_candidates()` | 步骤 5 | 记录触发上下文 |
| 调用主流程 | `diagnoses.run()` |  |  |
