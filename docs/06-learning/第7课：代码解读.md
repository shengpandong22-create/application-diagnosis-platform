# 企业 Adapter 消费链路 · 代码逐步骤解读

对应第 7 课。理解一条消息从RabbitMQ接收→解码/毒消息分流→process处理（其中通过DeduplicationStore做幂等）→ACK或retry→SMTP通知的完整过程。默认应用使用SQLAlchemy去重，Redis是可选Adapter。

## 概述：消费链路设计

```text
RabbitMQ Consumer.receive()
    → EnterpriseDiscoveryConsumer.consume_once()
        → ActiveDiscoveryApplicationService.process()
            → Incident 聚合 → TriggerPolicy → 创建 Diagnosis → run()
        → ACK（成功）/ retry（临时失败）/ reject（毒消息）
        → SMTP 通知（旁路，失败不影响 ACK）
```

### 核心文件：application/enterprise_consumer.py，总共 63 行。

### 步骤 1：接收消息（consume_once() 第 29-37 行）

```python
async def consume_once(self) -> EnterpriseConsumeResult:
    try:
        received = await self._source.receive()
    except asyncio.CancelledError:
        raise
    except Exception as error:
        return EnterpriseConsumeResult(consumed=False, broker_error=type(error).__name__)
    if received is None:
        return EnterpriseConsumeResult(consumed=False)
```

解读：

- `self._source` 类型是 `RabbitMQLogEventConsumer`——封装了 `aio_pika` 的 `IncomingMessage`
- `received is None`：队列为空，直接返回 `consumed=False`，让调用方决定是否休眠后重试
- `CancelledError` 必须 re-raise（asyncio 标准行为），其他异常包装为 `broker_error` 返回

### 步骤 2：处理事件（第 40-48 行）

```python
message, event = received
try:
    result = await self._discovery.process(event)
except asyncio.CancelledError:
    await asyncio.shield(message.retry())
    raise
except Exception:
    await message.retry()
    return EnterpriseConsumeResult(consumed=False)
```

#### 2.1 message 和 event 的分离

`received` 是一个元组：`(IncomingMessage, DiscoveredLogEvent)`。`IncomingMessage` 有 `ack()`、`retry()`、`reject()` 方法；`DiscoveredLogEvent` 是业务事件。

#### 2.2 CancelledError 特殊处理

```python
except asyncio.CancelledError:
    await asyncio.shield(message.retry())  # ← shield 保护重试不被二次取消
    raise
```

`asyncio.shield()` 保护 `message.retry()` 不被取消信号中断。设计意图：即使主任务被取消了，也要确保消息回到队列（否则消息丢失）。

#### 2.3 临时失败 → retry

```python
except Exception:
    await message.retry()
```

任意异常（LLM 调用失败、数据库暂时不可用等）→ `retry()`（`requeue=True`）→ 消息回到队列，等待重投。

### 步骤 3：ACK + 通知（第 49-63 行）

```python
await message.ack()

notification_error = None
if self._notifier is not None and result.triggered:
    try:
        await self._notifier.send(Notification(
            title=f"Incident {result.incident.exception_type}",
            summary="A bounded automatic diagnosis was triggered.",
            incident_id=str(result.incident.id),
            diagnosis_id=str(result.diagnosis_id) if result.diagnosis_id else None,
        ))
    except Exception as error:
        notification_error = type(error).__name__

return EnterpriseConsumeResult(True, result, notification_error)
```

#### 3.1 ACK 的位置有讲究

ACK 在 process 成功之后调用，不在 process 之前。如果 ACK 在 process 之前：

- process 失败 → 消息已经被消费 → 消息丢失

如果 ACK 在 process 之后：

- process 失败 → retry/reject → 消息不丢

#### 3.2 SMTP 通知是旁路

```python
if self._notifier is not None and result.triggered:
```

- `self._notifier is not None`：通知是可选的（单机运行时不配 SMTP）
- `result.triggered`：只有真正触发了诊断才发通知（不做无意义的告警）

通知失败只记录 `notification_error`，不回滚 ACK——诊断已经完成了，通知失败不应废除诊断。

#### 3.3 返回值包含通知错误

```python
return EnterpriseConsumeResult(True, result, notification_error)
```

即使通知失败，`consumed=True` 表示消息已被成功消费。`notification_error` 只是附带的诊断信息，供调用方日志/监控使用。

### 步骤 4：消费端调用方（入口）

`EnterpriseDiscoveryConsumer` 需要外部循环不断调用 `consume_once()`。典型模式：

```python
while True:
    result = await consumer.consume_once()
    if not result.consumed:
        await asyncio.sleep(1)  # 队列空或有错误，短暂休眠
```

## 失败模式详解

### 模式 1：临时失败（retry → 消息回到队列）

| 场景 | 行为 | 后果 |
| --- | --- | --- |
| process 抛未知异常 | `message.retry()` | 消息重新入队等待后续投递；RabbitMQ不保证回到原队列头 |
| 任务被取消 | `asyncio.shield(message.retry())` | 消息回到队列，任务终止 |

风险：如果永久性错误被当作临时失败处理（如格式非法的消息），会死循环消费 → 需要 `x-dead-letter-exchange` 配置和最大投递次数。

### 模式 2：毒消息（reject → DLQ）

`consume_once()`本身没有显式dead-letter分支：process异常会调用retry。毒消息在更前面的`RabbitMQLogEventConsumer.receive()`解码阶段被识别，并直接调用`message.dead_letter()`。当前应用代码没有维护普通处理异常的最大重试次数；是否通过Broker策略转入DLQ取决于外部队列配置，不能描述成代码已经自动实现。

### 模式 3：通知失败（降级，不影响 ACK）

```python
notification_error = type(error).__name__
return EnterpriseConsumeResult(True, result, notification_error)
```

通知失败不重新消费消息、不回滚 Incident/Diagnosis。诊断结果已经持久化，通知只是附带通知。

## 企业 Adapter 消费链路速查

| 步骤 | 关键代码 | 文件 | 设计原则 |
| --- | --- | --- | --- |
| 接收消息 | `_source.receive()` | `enterprise_consumer.py:31` | RabbitMQ `IncomingMessage` 包装 |
| 处理事件 | `_discovery.process(event)` | `enterprise_consumer.py:42` | 复用主动发现 + 被动诊断 |
| 取消保护 | `asyncio.shield(message.retry())` | `enterprise_consumer.py:44` | 取消时也必须回到队列 |
