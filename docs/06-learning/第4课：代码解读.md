# Evidence 生命周期 · 代码逐步骤解读

对应第 4 课。理解一条 Evidence 从工具产出 → 脱敏 → 落库生成正式 ID → 被结论引用 → `CitationPolicy` 校验 → 人工确认的完整过程。

---

## 概述：Evidence 不是"模型说了算"

Evidence 生命周期的核心设计哲学（`evidence_diagnoses.py` 第 4-7 行注释）：

> 入库前脱敏、创建用户/日志 Evidence、接受补充信息、记录人工确认。
> 后续改造时要守住一条原则：原始敏感文本不能先入库再脱敏，人工反馈也不能
> 覆盖模型原始结论，只能追加 Confirmation 和 Audit。

---

## 阶段 1：用户输入 → 诊断创建 + 初始 Evidence

源码位置：`application/evidence_diagnoses.py` 第 52-133 行（`create()`）

### 1.1 脱敏必须在持久化之前

```python
safe_symptom = self._redactor.redact(symptom)
safe_log = self._redactor.redact(submitted_log) if submitted_log else None
```

注释第 68 行强调："敏感文本必须在持久化和进入模型前完成脱敏，不能依赖事后清理。" 脱敏是不可逆的——一旦敏感数据落库，即使删掉也有 audit log 残留。

### 1.2 创建 DiagnosisCase + Evidence 在同一事务

```python
diagnosis = DiagnosisCase.create(title=..., symptom=safe_symptom.content, ...)

# 用户 symptom → Evidence(type=USER_STATEMENT, reliability=MEDIUM)
evidence = [Evidence.create(
    diagnosis_id=diagnosis.id,
    type=EvidenceType.USER_STATEMENT,
    content=safe_symptom.content,
    reliability=EvidenceReliability.MEDIUM,
    metadata={"untrusted_input": True, "redaction_count": ..., "redaction_categories": ...},
)]

# 用户日志 → Evidence(type=LOG_EXCERPT, reliability=HIGH)
if safe_log:
    chunks = _split_utf8(safe_log.content, Evidence.MAX_CONTENT_BYTES)
    for chunk in chunks:
        evidence.append(Evidence.create(type=EvidenceType.LOG_EXCERPT, content=chunk, reliability=HIGH))
```

**解读 - Evidence 可靠性等级**：

- `USER_STATEMENT` → `MEDIUM`（人口述可能有偏差）
- `LOG_EXCERPT` → `HIGH`（机器产生的事实）
- 工具产生的 → 由 `ToolLoopRunner` 决定（通常也是 `HIGH`）

### 1.3 按 hash 去重

```python
unique_evidence: dict[str, Evidence] = {}
for item in evidence:
    unique_evidence.setdefault(item.content_hash, item)
```

`symptom` 和 `submitted_log` 如果内容相同（例如用户把日志内容同时粘到了两个字段），只保留一条 Evidence。

### 1.4 大日志按字节切片

```python
chunks = _split_utf8(safe_log.content, Evidence.MAX_CONTENT_BYTES)
```

`_split_utf8()` 按 UTF-8 字节上限切分，不截断中文字符——逐字符累加字节数，超过上限时在前一个字符处断开。

## 阶段 2：Agent 调查 → 工具结果持久化为 Evidence

源码位置：`agent/runtime/tool_loop.py` 第 296 行

```python
evidence_ids = await self._persist_evidence(diagnosis.id, result)
```

每个工具调用结果（无论成功/失败）都有一个 `model_summary` 字段——这是模型看到的精简摘要（2000 字符限制）。同时 `result.evidence_drafts` 中包含想要正式记录的内容。

**关键**：`_persist_evidence()` 返回的是 `EvidenceStore` 生成的正式 Evidence ID。LLM 只能引用这些正式 ID，不能自己编 ID。`CitationPolicy` 只校验正式 ID 是否存在。

## 阶段 3：用户补充信息 → Evidence 追加 + 状态回滚

源码位置：`application/evidence_diagnoses.py` 第 146-210 行（`supplement()`）

```python
async def supplement(self, diagnosis_id, *, content, evidence_type):
    safe = self._redactor.redact(content)
    evidence = Evidence.create(
        diagnosis_id=diagnosis_id,
        type=evidence_type,
        source=EvidenceSource.USER_INPUT,
        content=safe.content,
        reliability=HIGH if evidence_type is LOG_EXCERPT else MEDIUM,
        metadata={"untrusted_input": True, "supplement": True, ...},
    )
```

### 3.1 状态守卫

```python
if diagnosis.status is not DiagnosisStatus.WAITING_FOR_INPUT:
    raise DiagnosisRunConflict(...)
```

只有 `WAITING_FOR_INPUT` 状态才能调用 supplement。进入 `WAITING_FOR_CONFIRMATION` 后，如需继续补充，应先执行 `continue_investigation` 回到 `INVESTIGATING`；`reject` 会进入终态，不能作为补充信息的前置动作。

### 3.2 hash 去重防止证据膨胀

```python
existing = await repository.find_by_hash(diagnosis_id, evidence.content_hash)
if existing is None:
    await repository.add(evidence)
else:
    evidence = existing  # ← 复用已有 Evidence
```

用户可能重复提交相同日志片段。hash 去重确保同一个诊断下不会出现两份完全相同的 Evidence。

### 3.3 状态回滚 + 审计

```python
expected_version = diagnosis.version
diagnosis.reopen_investigation()
await diagnoses.save(diagnosis, expected_version=expected_version)

await audits.add(AuditEvent.create(action="diagnosis.supplemented", ...))
```

补充信息后自动回到 `INVESTIGATING`，审计事件记录"谁补充了信息"。此时可以再次启动新的 AgentRun；`_start_investigation()` 对 `INVESTIGATING` 不重复推进状态，但后续仍会创建新AgentRun，因此不能把整个run流程称为幂等。

## 阶段 4：Candidate → CitationPolicy 校验

源码位置：`agent/runtime/tool_loop.py` 第 232 行

```python
citation_errors = await self._validate_citations(diagnosis.id, conclusion)
```

`_validate_citations()` 调用 `EvidenceCitationPolicy.validate()`，检查：

| 检查项 | 失败后果 |
|---|---|
| 引用 ID 是否存在 | → citation error |
| 引用归属当前 Diagnosis | → citation error |
| 引用等级是否匹配结论等级 | → citation error |
| 纯知识引用支撑 probable 结论 | → citation error（知识不能单独做高可靠结论） |

最多 2 次修正机会（`citation_correction_attempts < 2`），2 次后还不符合 → `INCONCLUSIVE`。

## 阶段 5：人工确认 → Confirmation + 状态终结

源码位置：`application/evidence_diagnoses.py` 第 212-282 行（`confirm_action()`）

```python
async def confirm_action(self, diagnosis_id, *, action, actor, comment):
    safe_comment = self._redactor.redact(comment).content if comment else None
    confirmation = Confirmation.create(diagnosis_id=diagnosis_id, action=action, actor=actor, comment=safe_comment)
```

### 5.1 三种动作

```python
if action is ConfirmationAction.CONFIRM:
    diagnosis.confirm()           # → CONFIRMED（终态）
elif action is ConfirmationAction.REJECT:
    diagnosis.reject()            # → REJECTED（终态）
else:
    diagnosis.reopen_investigation()  # → INVESTIGATING（继续查）
```

### 5.2 追加而非覆盖

注释第 222-224 行强调：

> 人工确认是独立事实：它追加 Confirmation 和 AuditEvent，不覆盖
> DiagnosisCase.conclusion 中保存的模型初始结论。

设计意图：保留"模型说了什么"和"人怎么判的"两条线，可以事后做评估对比。如果直接覆盖，就丢失了模型原始输出的审计链。

### 5.3 Reject 自动生成评测候选

```python
if action is ConfirmationAction.REJECT:
    candidate = EvaluationCandidate.create(
        diagnosis_id=diagnosis.id,
        source_action="human_reject",
        feedback_summary=safe_comment,
    )
```

被人类拒绝的诊断自动进入评测候选池。设计意图：被驳回的案例是最有价值的训练/调优素材。

## Evidence 生命周期速查

| 阶段 | 关键方法 | 文件 | 关键原则 |
|---|---|---|---|
| 用户输入 → Evidence | `create()` | `evidence_diagnoses.py:52` | 先脱敏、再入库、hash 去重、大日志切片 |
| 工具产出 → Evidence | `_persist_evidence()` | `tool_loop.py` | 只持久化实际产生的draft并返回formal ID；LLM引用其他ID会被校验拒绝 |
| 补充信息 → Evidence | `supplement()` | `evidence_diagnoses.py:146` | 仅 `WAITING_FOR_INPUT` 可用、hash 去重、自动回到 `INVESTIGATING` |
| 结论引用校验 | `_validate_citations()` | `tool_loop.py` | `CitationPolicy`校验：ID属于当前Diagnosis、probable需要用户/日志、possible需要验证建议、模型不能confirmed |
| 人工确认 | `confirm_action()` | `evidence_diagnoses.py:212` | 追加 Confirmation 不覆盖 conclusion、Reject→评测候选池 |
