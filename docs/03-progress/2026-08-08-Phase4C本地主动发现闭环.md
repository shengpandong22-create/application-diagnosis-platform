# 2026-08-08：Phase 4C 本地主动发现闭环

## 1. 阶段目标

Phase 4C 在不引入 MQ、Redis 和常驻 Worker 的前提下，完成可重复的本地主动发现链路：

```text
FileSource / ReplaySource
  → Schema 与路径边界
  → 服务目录映射
  → 入库前脱敏
  → Fingerprint / Incident 聚合
  → DiagnosisTriggerPolicy
  → Diagnosis + 初始 Evidence + Audit
  → 有界 ToolLoopRunner
  → Report / Trace 关联 Incident
```

## 2. 关键设计决定

### 2.1 摄取与触发分离

`POST /api/v1/incidents/events` 仍然只聚合事实，不调用模型。`POST /api/v1/discovery/replay` 才进入主动发现编排，避免所有日志摄取都隐式产生费用和副作用。

### 2.2 可恢复触发语义

TriggerPolicy 判断的是 Incident 是否已经关联 Diagnosis，而不是只看 `is_novel`：

- 没有关联：允许创建一次 Diagnosis；
- 已关联：重复日志只增加 occurrence，不再次调用模型；
- 模型运行失败：保留关联和所有事实，不自动盲重试；
- 创建 Diagnosis 前失败：后续 Replay 仍有机会恢复。

Phase 4C 使用单机编排锁配合数据库一对一约束。分布式声明与消息恢复留给可选 Phase 4E。

### 2.3 安全边界

- FileSource 只能读取显式根目录下的相对路径；
- 文件大小受限，JSONL 逐行校验；
- 服务必须存在，环境必须匹配；
- message 在 Incident、Evidence 和模型上下文之前脱敏；
- ServiceProfile 决定源码、日志、配置和健康检查访问范围；
- 模型结论仍由 CitationPolicy 和 Diagnosis 状态机收敛，不能直接 confirmed。

## 3. 新增能力

- `LogEventSource` Port；
- `ReplayLogEventSource`；
- 受限 `FileLogEventSource`；
- `DiagnosisTriggerPolicy`；
- `ActiveDiscoveryApplicationService`；
- Incident–Diagnosis 一对一关联与 Alembic `0012`；
- Replay API；
- Report/Trace 主动发现来源；
- 默认 Fake LLM 演示与一键验收。

## 4. 失败保留

Agent 失败时不回滚已经成立的事实。测试覆盖 Incident、Diagnosis、初始 Evidence、AgentRun、ToolRun 和 AuditEvent 仍可追踪。Runner 将模型传输失败转换为受控 termination reason，而不是让异常破坏整个发现事务。

## 5. 未实施边界

- 不持续 tail 文件；
- 不启动后台 Worker；
- 不接 RabbitMQ、Redis 或日志平台；
- 不自动重试真实模型；
- 不做跨实例并发消费。

这些能力只有在本地闭环稳定且确有企业接入展示需求时再进入 Phase 4E。
