# 2026-08-08：Phase 4D 运营复盘与反馈回流

## 1. 阶段目标

Phase 4D 让主动发现结果具备取证、运营统计和人工纠错回流能力，同时避免自动反馈污染知识库或正式评测集。

```text
授权日志 + trace_id + UTC窗口
  → related_logs__query
  → 脱敏 Log Evidence

Incident / Diagnosis 事实
  → 服务日摘要 JSON / Markdown

人工 reject
  → EvaluationCandidate(candidate)
  → 人工 label
  → 显式 promote
```

## 2. 相关日志安全边界

- 仅允许 ServiceProfile 授权目录内的 `.log/.txt` 相对路径；
- 必须提供 trace_id、UTC 时间范围和数量上限；
- 时间范围最多 24 小时，结果最多 50 条；
- 输出仍受 Tool 字节预算限制；
- 每条结果带文件和行号引用，并在进入 Evidence 前脱敏。

## 3. 日摘要事实口径

摘要不建立独立统计表，而是按 UTC 日期从 Incident 和 Diagnosis 实时计算：新指纹、Incident 数量、发生次数、高频故障、待确认和驳回数量。Markdown 不包含日志正文和敏感信息。

## 4. 反馈隔离

人工 reject 自动创建 `candidate`，但不会修改知识库或 `evals/cases`。候选必须引用本 Diagnosis 的 Evidence，经过人工 label 后才能显式 promote。趋势第一版只按状态和 Prompt 版本计数，不把样本量变化包装成质量提升。

## 5. 阶段边界

Phase 4D 不实现 MQ、Redis、跨实例 Worker、通知和自动修改静态评测文件。至此 Phase 4A～4D 的本地主动发现闭环完整，Phase 4E 仍为按需可选企业接入展示。
