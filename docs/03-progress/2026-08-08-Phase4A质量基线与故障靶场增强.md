# 2026-08-08：Phase 4A 质量基线与故障靶场增强

## 1. 阶段目标

Phase 4A 不改变日志接入方式，也不引入MQ、Redis、LangGraph或向量检索。目标是先建立可重复的质量评价尺子，再扩大故障样本覆盖范围，为后续Fingerprint、Incident和主动触发提供回归基线。

## 2. 已完成能力

### 2.1 版本化评测上下文

每个EvaluationCase现在可以绑定：

- dataset version；
- model id；
- prompt version；
- strategy version；
- tool schema version；

旧Phase 0C案例仍可加载，未填写的新字段使用`unspecified`，避免升级评测契约破坏历史数据。

### 2.2 质量指标

EvaluationSuite新增：

- 分类准确率和混淆矩阵；
- 根因Top-1/Top-3命中率；
- Evidence引用precision/recall；
- unsupported claim比例；
- 信息充足性识别率；
- 工具选择匹配率；
- 高置信错误率；
- 平均延迟、Token和估算费用；
- 原有结构化输出、终止原因、Evidence和工具成功率。

评测器会明确拦截：不存在的Evidence引用、有事实状态但没有Evidence的结论、缺失要求工具、错误分类以及禁止根因词。

### 2.3 Java Lab扩展

Java Lab从3类扩展到8类确定性故障：

| 案例 | 分类 | 理想上下文深度 |
|---|---|---|
| NPE | code_bug | cross_file |
| 连接拒绝 | dependency | config |
| Inventory超时 | dependency | config |
| ConcurrentModificationException | code_bug | class |
| 必需配置缺失 | config | config |
| 连接池耗尽 | config | config |
| 非法请求参数 | external | class |
| 下游超时后上游NPE | dependency | related_logs |

每个案例均包含触发入口、日志关键词、预期分类、代码路径、Evidence类型、理想工具和根因词。连锁异常通过`lab-chain-001`保留相关标识，为Phase 4D的相关日志工具准备ground truth。

### 2.4 配置路由问题修复

真实模型评测发现，Strategy Router中宽泛的`exception`和`HTTP 500`规则会与配置规则打平，导致明确配置异常回退到Generic Strategy。Phase 4A移除了这两个低信息量规则：

- 明确NPE和stack trace仍进入Application Strategy；
- 明确连接和超时进入Network Strategy；
- 明确缺失配置进入Configuration Strategy；
- 未知异常和普通HTTP 500回退Generic；
- NPE与连接拒绝同时出现时仍按冲突规则回退Generic。

该行为已通过确定性路由测试固定。

- 结果：通过；
- 4轮、8次工具调用；

- 约20.7秒；

该结果证明质量正确，但工具搜索重复、Token成本偏高，后续可作为快慢路径与工具去重优化基线。

### 缺失配置

该场景在加强验收前曾仅凭日志和源码得到正确文本结论，但加强为“必须调用`config__read`并引用`config_excerpt`”后未通过。

失败原因不是模型无法理解异常，而是确定性Strategy Router受到宽泛application信号干扰，没有稳定进入Configuration Strategy。本轮最后一次调用后完成了规则修复和离线回归，遵守低频调用约束，不继续做第5次调用。
