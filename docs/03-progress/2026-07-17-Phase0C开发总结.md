# 2026-07-17 开发总结：Phase 0C 评测、报告与极简界面

> [返回文档导航](../README.md)

## 1. 阶段目标

Phase 0C 把 Phase 0B 的证据闭环继续扩展为可评测、可交付、可操作的最小产品形态。

最终验证结果：Ruff 通过，pytest `149 passed`，固定评测 `2/2 passed`，空库迁移、Alembic 漂移、OpenAPI 和评测契约均通过。

## 2. 已完成

### 2.1 离线评测

- EvaluationCase、Observation、Result 和 Suite 契约；
- 确定性评测结构化输出、Evidence 引用、必要证据类型、工具成功率、终止原因和根因关键词；
- `evals/cases/phase0c-baseline.json` 固定基线；
- CLI 输出机器可读 JSON；
- 默认不访问网络、不调用真实模型。

### 2.2 诊断报告

- DiagnosisReport Domain DTO；
- 聚合 Diagnosis、Conclusion、Evidence、AgentRun 和 Confirmation；
- 构造时校验引用 Evidence 属于当前 Diagnosis；
- JSON 报告 API；
- Markdown 报告 API；
- 报告生成不再次调用模型。

### 2.3 极简界面

- FastAPI 提供 `/ui`；
- 原生 HTML/CSS/JavaScript，无独立前端构建；
- 支持创建、查看、运行、补充、确认、驳回、继续调查和报告查看；
- UI 只调用 API，不复制领域规则。

## 3. 设计经验

- 系统规则回归与真实模型质量评测必须分开；
- 报告是已有事实的投影，不应隐式再次调用模型；
- 报告引用校验要在聚合边界再次执行，不能只相信历史写入；
- UI 是用例入口，不应成为新的业务规则中心；
- 个人项目先用无构建工具界面验证闭环，再决定是否需要独立前端。

## 4. 暂缓内容

- 向量或混合检索；
- Worker 与任务队列；
- 完整身份认证和 RBAC；
- 自动真实模型评测；
- 报告持久化、签名和版本管理；
- 独立前端工程。
